## Reflection Questions
1. `topIndex` will hold the value 0 immediately after construction, that specific value makes `isEmpty()` return the right answer without special casing because, in my code, the logical stack is not 0-indexed. The index will only be zero when nothing has been pushed, or everything has been popped.
2. when `push`is called, an if statement first calls on `isFull` to check if the stack is logically full, not if all the `data` elements have been assigned a value. If there is space to push the next step of the function is to assign the integer from the `value` parameter into the array. The value of `topIndex` is used to select which index in the array `value` is assigned to. Next `topIndex` will increment by one. Reversing this order would break the stack because the index would skip the first element of the array which reduces maximum size, making the `isFull` method inaccurate; `pop` would still be logically correct, but the incorrect offset of the index of `value` means that the `peek` method would always be incorrect.
3. The time complexity for each method in Big-O is O(1). `push` will always run the same basic operations regardless of the size or position of the stack. None of the methods require looping to visit each element of the array, and if it did we would not need to iterate an N number of times because the array size is fixed. 
4. When `push` is called and the stack is full, the if statement will catch that there is no more space to add more values, and instead it will move to an else line where it will print "Stack is Full". Nothing gets returned since the method return type is void. topIndex does not change. The purpose of this behavior is to let the user know that the reason they won't find a value being added or the index being shifted is because the stack has reached maximum capacity. There is no possible functional error.
5. When `pop` or `peek` is called and the stack is empty, their if statements will check that stack is empty and write these messages respectively, "pop: Stack is empty", and "peek: Stack is empty". These messages show the user why the expected result didn't happen, and display during which method was it recognized that the stack is empty. the `pop` method has no return datatype. `Peek` will return integer 0 in the case of an empty stack, since primitive data types do not have null, and the default is 0.
6. If a caller needed more room than 100 slots, and knew exactly by how many slots they would increase: I would have to change the size of `data` first in the header file, then the only method in the .pp file that would need to be altered is the `isFull` method to match the maximum index. This would produce no change in terms of the time complexity given in question 3 since the number of basic operations belonging to each method remains the same, and we still never require loops or iterating an operation an N number of times.
7. If this stack were built on a linked list instead, if I remember correctly, linked list are not constructed with a fixed number of slots. And values are not assigned in memory to a continuous block, but rather each element has a pointer to their own spaces in memory. One advantage of these differences would be that we would never have to alter the code to change the number of slots in the stack. A disadvantage could be that, in the case of larger stacks, memory usage and runtime could become much larger than an array based stack.
